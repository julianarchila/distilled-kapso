# Working in this repo

This repo builds one [distilled](https://github.com/alchemy-run/distilled) SDK,
`@julianarchila/kapso`, outside the distilled monorepo. It follows distilled's rules,
procedures and style; this file lists only what differs. Read [`vendor/distilled/AGENTS.md`](vendor/distilled/AGENTS.md) first: its 15 rules apply
here unchanged, and reviewers cite them by number.

## Layout

```
packages/kapso/          the SDK, laid out exactly as packages/<pkg> upstream
packages/core -> vendor/distilled/packages/core   (symlink)
packages/dev  -> vendor/distilled/packages/dev    (symlink)
vendor/distilled/        git submodule, pinned to a distilled release tag
stacks/distilled-submodules/spec-repos/kapso/   the spec mirror's fetch script, at its upstream path
scripts/                 repo tooling: fetch-specs, derive-whatsapp-message-patch
```

## What differs from upstream

1. **The generator comes from the submodule.** `@distilled.cloud/dev` is not published, so
   `vendor/distilled` is pinned to a release tag and `packages/core` and `packages/dev` are
   symlinks into it. The package's `tsconfig.json`, `package.json` (`workspace:*`) and scripts are
   therefore what they would be upstream (except the package name, see 5). Generated code and core must come from the
   same tag: to move, check out the new tag in the submodule, copy its catalog versions into
   `pnpm-workspace.yaml`, run `pnpm install && pnpm generate`, and commit the submodule, the
   lockfile and the regenerated `src/services/` together.
2. **The spec is committed, not mirrored.** There is no `distilled-mirror/spec-mirror-kapso`.
   `pnpm specs:fetch` runs `stacks/distilled-submodules/spec-repos/kapso/fetch-specs.ts` and writes
   `packages/kapso/specs/spec-mirror-kapso/specs/openapi-whatsapp.yaml`, the path a submodule
   would hold upstream, so `scripts/convert.ts` reads the same path in both places.
3. **Evidence lives where upstream keeps it.** A patch's `description` says what the spec gets
   wrong, what the wire does and when it was observed; the PR or commit body carries the request
   and response (rule 7). Raw responses are not committed. Anything quoted from a live call (in a
   description, a test body or a commit) is sanitized: no API keys, phone numbers, message ids
   (`wamid`s encode the phone number in base64), business-scoped user ids (`CO.<digits>`),
   conversation ids, tokens, media URLs (Kapso's `media_url` downloads without a key), message
   text or contact names.
4. **One patch is derived by a script.** `patches/001-whatsapp-message.json` works around a
   converter limit (an `anyOf` of required-only branches read as a union). It is regenerated by
   `scripts/derive-whatsapp-message-patch.ts`, never edited by hand. The real fix belongs in
   distilled's converter (rule 6); if it ever reads such branches as a constraint, `pnpm
   patches:audit` reports the patch as unneeded.
5. **The package is published under another name.** It is `@julianarchila/kapso` on npm, since
   only distilled publishes under `@distilled.cloud`; everything else in `packages/kapso/` is laid
   out as upstream. To release: bump `version` in its `package.json`, `pnpm build`, then
   `pnpm --filter @julianarchila/kapso publish`. pnpm replaces `workspace:*` with the exact core
   version, which must be one published on npm (the submodule's release tag).

## Everyday commands

```sh
git submodule update --init --depth=1   # once, after cloning
pnpm install
pnpm generate          # convert + patches + generate + format
pnpm typecheck:ci      # tsrs -b --noCheck false (what CI runs)
pnpm test              # vitest: the hand-written protocol, media helper and webhooks
pnpm lint              # oxlint with distilled's plugin (rule 4)
pnpm format            # oxfmt
pnpm specs:fetch       # refresh the spec
```

Node 24, pnpm 12. Scripts that import workspace packages run with `node --conditions=bun`.

## Live calls

Live calls follow distilled's method (`vendor/distilled/.agents/skills/distilled-sdk-patch/SKILL.md`,
step 1): reach the code path you want to prove, create throwaway resources and delete them, never
print credentials, and record only what you observed. To find spec gaps, call read-only
operations through the SDK under `ResponseValidation.strict`: every failure is a response the
model does not describe. A sandbox number serves only the messaging
endpoints (403 elsewhere), and sends reach only numbers that joined the sandbox; every inbound
message reopens that number's 24-hour window.
